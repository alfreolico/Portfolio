Active capability

What I can build

I work on defined projects: from a landing page or professional site to a small application, integration, or dashboard, based on the context and available information.

Main services

A web response for a concrete problem

Every collaboration starts with the objective, audience, constraints, and available evidence; technology supports that decision.

01 · Applied

Landing pages and conversion pages

Solves: presenting an offer, collecting registrations, promoting an event, sharing a personalized web invitation, or guiding toward a clear action.

  • Responsive page and content hierarchy.
  • CTAs, a registration form or link when the external service is defined, and personalized web invitations with an agreed scope.
  • Google Analytics and static publishing when included in scope.

For: professionals, events, and businesses with one main action or a personalized digital invitation.

Evidence: KYK Webinar, portfolio, and digital card; Be My Valentine as an exploration of an interactive format.

02 · Applied

Professional and business sites

Solves: scattered information, missing digital presence, or a presentation that does not explain services and contact.

  • Responsive multipage site, navigation, and organized content.
  • Services, contact, social links, and basic analytics.
  • Bilingual version when content is available.

For: professionals and small businesses with a clear offer.

Evidence: multipage portfolio and digital card.

03 · Applied

Portfolios and professional presence

Solves: generic profiles, projects without context, or a lack of visual evidence of work.

  • Content architecture and responsive portfolio.
  • Projects page, case studies, and professional links.
  • Visual theme and bilingual version depending on scope.

For: professionals who need to explain their work clearly.

Evidence: Alfredo's portfolio.

04 · Applied

Digital cards

Solves: sharing contact and services in a mobile, direct way that is more practical than a printed card.

  • Mobile page with contact details, social links, and services.
  • Visual identity and links to WhatsApp, email, or social networks.
  • QR code when defined as part of the scope.

For: independent professionals and local services.

Evidence: digital card for professional services.

05 · Defined scope

Web applications with a defined scope

Solves: consulting information, organizing data, capturing entries, or running simple flows.

  • Web interface, interaction, forms, and navigation.
  • API consumption and a simple backend when the scope requires it.
  • Basic documentation of completed work.

For: teams or businesses with a small internal tool and a concrete need.

Evidence: React and JavaScript projects; industrial platform in development.

06 · In-development project

Dashboards and data visualization

Solves: hard-to-read data, limited visibility of states, or distributed information.

  • Indicator cards, tables, charts, and states.
  • Basic filters when scope defines them.
  • Integration with an available data source.

Scope note: depends on the availability, structure, and permissions of the data source.

Evidence: industrial monitoring web platform in development.

07 · Applied

API and web service integration

Solves: showing external information, connecting an interface to a documented service, or centralizing data.

  • Data consumption and transformation.
  • Basic state and error handling.
  • Frontend–backend connection and environment variables when needed.

For: projects with a documented API and available access.

Evidence: public APIs and platform in development.

08 · Applied

Site maintenance and evolution

Solves: functional but disorganized sites, confusing navigation, inconsistent design, or hard-to-maintain content.

  • Initial review and priority list.
  • Fixes, controlled refactoring, and responsive improvements.
  • Basic accessibility adjustments and change documentation.

For: existing sites that need order and staged improvements.

Evidence: evolution of the current portfolio.

How I approach a project

A conversation before a solution

  1. Initial conversation

    I listen to the goal and context.

  2. Problem

    We define what the solution needs to solve.

  3. Scope and constraints

    We review data, access, content, and limits.

  4. Proposal

    I outline a solution structure, in phases when useful.

  5. Implementation

    I build and review progress in manageable blocks.

  6. Review and delivery

    We validate agreed criteria and document what is needed.

  7. Maintenance

    It can continue when contracted as part of the next scope.

Collaboration conditions

Information and boundaries before committing to a solution

What I need from the client

Information that improves the conversation

  • Goal and audience.
  • Available content and visual references.
  • Required functions and desired date.
  • Access or documentation for external services.
  • Constraints and approval owner.

Scope and boundaries

Validate before committing

Before committing to a solution, I review scope, data sources, external services, permissions, and validation criteria.

More complex projects may need stages, additional tests, external services, infrastructure, or collaboration with other profiles.
