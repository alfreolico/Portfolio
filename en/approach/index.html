02 · Process

How I approach a problem

Before choosing a tool, I review the need, context and constraints. The process makes that judgement visible.

  1. 01 · Input
  2. 02 · Control
  3. 03 · Flow
  4. 04 · Transmission
  5. 05 · Inspection
  6. 06 · Return

01 · Input / receive

Understand the problem

I identify the need before choosing a tool. The goal is to understand what the solution needs to resolve and for whom.

02 · Control / decide

Review constraints and data

Before committing to a solution, I review scope, information and data sources, access, permissions, constraints and project limits.

03 · Flow / organize

Design a structure

I divide the system into understandable screens, components and flows so information can be reviewed and evolved.

04 · Transmission / transfer

Prototype and implement

I turn the structure into a functional, reviewable interface, connecting components and data according to the defined scope.

05 · Inspection / verify

Validate before closing

I verify behavior, record relevant decisions and iterate from findings, not from a feeling of closure.

06 · Return / evolve

Maintain and evolve

A solution can continue through maintenance, fixes and phased improvements when there is a clear new scope.
